# Бэклог Buyerly

Сверка документации после PR #140. Это список направлений, а не обещание сроков или подтверждение внешних разрешений Meta. Перед реализацией создаётся отдельная задача с критериями готовности и проверяется текущий код.

## Уже есть в коде

Повторно планировать с нуля не нужно: React Inbox, Ads Manager и Statistics; OAuth с invite-ссылками; workspace-роли и серверные сессии; analytics fact store; правила campaign/adset/ad и безопасная отмена поддерживаемых действий. Реализация не означает полную готовность всех сценариев и прохождение пользовательской приёмки.

## Направления дальнейшей работы

| Направление | Что уточнить или завершить |
|---|---|
| Правила | Preview/наблюдение до активации и объяснение конфликтов. Пауза между повторными действиями задаётся в редакторе (Repeat, #194). |
| Аналитика | Сравнение периодов, произвольные даты, дополнительные метрики, графики, CSV и большие выборки; проверять поддержку backend перед добавлением UI. |
| Доступность и mobile | Полный responsive-проход, reduced motion, keyboard/focus и browser E2E. Действующие ограничения указаны в UI-контракте. |
| Meta rollout | Подтверждение реального app-role пилота и доступа внешних профилей в Meta Dashboard; код OAuth уже существует. |
| Эксплуатация | Уточнение покрытия watchdog/heartbeat и диагностики частичных сбоев, проверяемое восстановление и мониторинг. |
| Обучение | Краткие инструкции пользователя по подключению, назначениям правил, метрикам и отмене действий. |
| Будущие модули | Tracker/revenue, креативы, страницы и комментарии — отдельные продуктовые решения, не текущие функции. |

Конкретные задачи ведутся в GitHub Issues.
