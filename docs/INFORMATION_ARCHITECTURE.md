# Buyerly Information Architecture

Buyerly использует workspace-first URL без технического префикса: сразу после
домена идёт читаемый slug команды. В интерфейсе нет свободной регистрации и
переходов со старых адресов.

## Jobs-to-be-done

| Задача пользователя | Раздел | Результат |
| --- | --- | --- |
| Увидеть, что требует внимания | Inbox | Уведомления, состояние и быстрые действия |
| Увидеть все рекламные кабинеты и их день | Ad accounts | Статус, расход и лиды за сегодня, правила и подключение каждого кабинета |
| Управлять рекламной структурой | Ads Manager | Campaigns, Ad sets и Ads |
| Настроить повторяемое действие | Rules | Правила, группы и назначения |
| Изменить параметры продукта | Settings | Профиль, workspace и интерфейс |

## Навигация

Единый порядок основного desktop-сайдбара:

1. Inbox
2. Ad accounts (G K)
3. Ads Manager
4. Rules
5. Settings

Ad accounts — как Projects в Linear: список кабинетов workspace и страница
каждого (#388). Кампании, ad sets и объявления живут в Campaigns, который, как
Issues команды в Linear, показывает все кабинеты сразу: по умолчанию сгруппированные
по кабинету (Display → Grouping: Ad account), с фильтром Ad account. Переключателя
кабинетов и «+» в шапке нет: кабинет подключают в Ad accounts, и он сразу
появляется в Campaigns. «Open campaigns» на странице кабинета открывает Campaigns
с фильтром «Ad account is …». My campaigns — тот же список по кабинетам, где ты
Lead, со своими Display options, как My issues в Linear.

Внутри Ads Manager тип сущности является частью URL, поэтому ссылку на список
или конкретную запись можно сохранить и отправить коллеге.

## Канонические URL

| Экран | Канонический URL |
| --- | --- |
| Вход | `/login` |
| Регистрация | `/signup` |
| Одноразовая ссылка из письма | `/auth/email/verify?token=…` |
| Вход ещё в один аккаунт (Add an account…) | `/auth/add-account` |
| Создание первого workspace | `/create-workspace` |
| Принятие приглашения | `/invite/{token}` |
| Настройка профиля и приглашение команды | `/{workspace}/welcome` |
| Inbox | `/{workspace}/inbox` |
| Элемент Inbox | `/{workspace}/inbox/{itemId}` |
| Ad accounts | `/{workspace}/accounts` |
| Рекламный кабинет | `/{workspace}/accounts/{accountId}` (`act_…`) |
| Campaigns | `/{workspace}/ads-manager/campaigns` |
| Ad sets | `/{workspace}/ads-manager/adsets` |
| Ads | `/{workspace}/ads-manager/ads` |
| Конкретная рекламная сущность | `/{workspace}/ads-manager/{entityType}/{entityId}` |
| Rules | `/{workspace}/rules` |
| Правило | `/{workspace}/rules/{ruleId}` |
| Удалённые правила и группы (Recently deleted, 30 дней) | `/{workspace}/rules/recently-deleted` |
| Settings | `/{workspace}/settings` |

Открытие `/{workspace}` канонизируется клиентом в `/{workspace}/inbox`.
Префикс `/w/`, корневые shortcuts и другие legacy aliases не поддерживаются и
не перенаправляются.

Адрес записи открывает её на своей строке: список прокручивается к ней и даёт
ей фокус, а фильтр, вкладка или свёрнутая группа, которые её прячут, снимаются.
Campaigns показывает все кабинеты, поэтому запись находится по одному адресу;
`?account={accountId}` в ссылках на запись остаётся и ни на что не влияет, а старая
ссылка `/{workspace}/ads-manager/campaigns?account={accountId}` превращается в
фильтр «Ad account is …». Найденный кабинет (поиск, палитра O K)
открывает его страницу `/{workspace}/accounts/{accountId}`. По этим адресам результаты открывает страница поиска
`/{workspace}/search?q=…&type=…` (`/` и лупа в сайдбаре), как в Linear: она ищет
кампании, ad sets, объявления, правила и рекламные кабинеты только текущего
workspace, а запрос, вкладка, фильтры (`status`, `account`) и Display options
(`order=updated`, `includeDeleted=true`) живут в адресе. Второй Esc уходит туда,
откуда поиск открыли. Ctrl/Cmd+K, как в Linear, — отдельное меню команд, а O и буква (C, A, D, R,
K, S) — палитры «Open …» для быстрого перехода к записи того же адреса.

## Авторизация и первый вход

- `/login` и `/signup` повторяют Linear: только вход через email (Google, SSO и
  passkey нет), между ними ссылки «Don’t have an account? Sign up» и «Already
  have an account? Log in». Паролей нет, как в Linear.
- Письмо содержит одну одноразовую ссылку и соответствующий шестизначный код.
  Использование любого варианта сразу аннулирует второй.
- Регистрация открыта: код получает любой email. Новый email без приглашения
  сначала проходит проверку Cloudflare Turnstile.
- Новый пользователь без workspace проходит `/create-workspace`, затем
  `/{workspace}/welcome`: сначала Name, затем необязательные приглашения.
- Пользователь по invite сначала вступает в заданный workspace, затем при
  необходимости заполняет только Name. Поля Title нет.
- Занятый или системный slug возвращает ошибку под полем. Buyerly не создаёт
  варианты с числовыми суффиксами автоматически.

## Терминология

| Канонический термин | Значение |
| --- | --- |
| Workspace | Изолированная команда и её данные |
| Campaign | Кампания Meta Ads |
| Ad set | Группа объявлений Meta Ads |
| Ad | Объявление Meta Ads |
| Rule | Автоматизация, проверяющая условия и выполняющая действие |
| Inbox | Поток уведомлений и требующих внимания событий |

## Роли и видимость

Роли повторяют Linear. Команда объединяет людей и рекламные кабинеты; у кабинета
есть Lead — ответственный баер.

| Возможность | Owner | Admin | Member | Guest |
| --- | --- | --- | --- | --- |
| Просмотр кабинетов | Публичные команды и без команды; приватные — после вступления | То же | То же | Только своих команд |
| Работа с кабинетом (Ads Manager, правила на кабинете, Lead) | Да | Да | Да | В своих командах |
| Общие Rules, метки, подключения Meta | Да | Да | Да | Нет |
| Создание команд | Да | Да | Да | Нет |
| Управление командой | Все команды | Все команды | Свои, где он Team owner | Нет |
| Приглашение участников | Да | Да | Нет | Нет |
| Настройки workspace | Да | Да | Нет | Нет |
| Передача владения и удаление workspace | Да | Нет | Нет | Нет |

Приватную команду (как в Linear) видят только её участники; админ видит её в Settings и может вступить.

Team owner — роль в команде, как в Linear: создатель команды становится её
владельцем, владелец или админ может сделать владельцем другого участника
команды (не гостя).

Информационная архитектура не заменяет backend RBAC: недоступные мутации должны
быть скрыты в UI и отклонены API.

## Локализация

Тексты нового прототипа следуют согласованной английской терминологии Linear-like
интерфейса. Email и URL-slug остаются техническими идентификаторами.

## Длинные списки

Списки рекламных сущностей и правил используют поиск, фильтры, видимый счётчик,
отдельные empty states и сохранённые представления. URL сохраняет тип сущности и
идентификатор открытой записи.

## Definition of Done

- Все пользовательские страницы доступны только по таблице канонических URL.
- Зарезервированы только корневые сегменты, которые обслуживает сам сервер; остальные слаги свободны.
- Вход по ссылке и коду одноразовый.
- Занятый workspace URL не изменяется автоматически, а объясняется пользователю.
- Owner и приглашённый участник проходят только относящиеся к ним шаги welcome.
- Контракты frontend, API и маршрутов проходят в GitHub Actions.
