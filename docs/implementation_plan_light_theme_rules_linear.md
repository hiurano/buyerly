# План: светлая тема Rules по паттерну Linear My issues

## Цель

Привести представление `Rules` в светлой теме к фактическому паттерну Linear `My issues → Assigned`: читаемая типографика, нейтральная групповая шапка на всю ширину списка, строки без тёмных-theme значений и согласованные состояния hover/focus/selected. Функциональная модель правил и фильтров не меняется.

## Зафиксированные проблемы

- В `RuleRow` захардкожены тёмные значения: белый заголовок, белые полупрозрачные подложки и hover. На светлом canvas они дают почти нулевой контраст.
- В `RuleGroupHeader` захардкожены тёмный градиент и белый текст. Это превращает группы в тёмные плашки вместо нейтральных full-width заголовков Linear.
- В связанных панелях Rules есть аналогичные dark-only значения (`text-white`, `hover:text-white`, `bg-white/...`, LCH с низкой светлотой); они должны быть заменены семантическими токенами или theme-aware значениями.
- Заголовок группы в Linear имеет высоту 36 px, фон `--bg-sidebar` и текст 13 px / 500; текущая структура Rules близка по размеру, но неверна по цветовой модели и визуальному весу.

## Эталон Linear, снятый с My issues → Assigned

- Canvas: светлый inset-контейнер; заголовок раздела 13 px / 500; вкладки — 28 px pill, выбранная вкладка на `--tab-active-bg`.
- Группа: широкая плашка 36 px с фоном цвета sidebar, без цветного градиента; внутри collapse, индикатор, название 13 px / 500, счётчик и `+` справа по hover.
- Строка: 44 px; основной текст — контрастный `--text-primary`, вторичные данные — `--text-secondary` / `--text-tertiary`; фон только для hover, keyboard focus и selection.
- Цвет применяется только как компактный семантический маркер (toggle, статус, action badge), а не как тёмная подложка или цвет текста, рассчитанный на dark mode.

## План реализации

1. Инвентаризировать все hard-coded dark tokens в `frontend/src/components/rules/` и классифицировать их: текст, поверхности, границы, hover/focus, статусы. Не затрагивать состояние данных и сценарии работы Rules.
2. Сформировать небольшой набор theme-aware семантических токенов для строк Rules и action badges в `frontend/src/styles/tokens.css`; для light mode подобрать значения по визуальному референсу Linear, для dark mode сохранить текущую читаемость.
3. Переработать `RuleGroupHeader.tsx`: убрать тёмный градиент и белый текст, использовать нейтральную 36-px full-width group header, токены текста/hover и безопасные контрастные цвета иконки/счётчика.
4. Переработать `RuleRow.tsx`: заменить все direct `#fff`, `white/[...]` и dark LCH на токены; разделить уровни типографики, нормализовать borders/backgrounds condition/scope/action badges и состояния hover/focus/selected.
5. Довести вспомогательные поверхности Rules до той же темы: list empty state, display/filter popovers, board/new-group state, create-rule modal и right sidebar. Сохранить компоненты функционально неизменными.
6. Сверить список в браузере side-by-side с открытым Linear: геометрия header/tabs/groups/rows, контраст обычных и paused правил, hover, collapse, filters, display modes, popovers и responsive-режим.
7. Проверить только удалённый GitHub Actions после push; локальные тестовые команды не запускать согласно `AGENTS.md`.

## Критерии готовности

- На Rules в light theme нет белого/светлого текста на светлом фоне и нет тёмных group bars.
- Все тексты и интерактивные состояния различимы без hover.
- Визуальная иерархия списка (tabs → group header → row → metadata) соответствует Linear My issues.
- Поведение фильтров, групп, переключателей, выбора строк и панели details не изменилось.
