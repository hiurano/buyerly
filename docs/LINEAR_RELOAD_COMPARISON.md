# Перезагрузка Linear и Buyerly (#433)

Замерено 20.10.2026 во встроенном браузере (Chrome, 1024×768, h3 через Cloudflare, Амстердам), Linear — рабочее пространство `buyerly-test`, Buyerly — `test` на buyerly.app. Тёмная тема снималась через системную тему вкладки, светлая — так же, без смены настроек аккаунтов.

## Что видит человек при перезагрузке Linear

1. **Первый кадр (≈350 мс, first paint)** — уже «рамка» приложения, без логотипа и спиннера: фон сайдбара на всё окно и панель контента со скруглением 12px, рамкой 0.5px и отступами как у настоящего приложения (слева ширина сайдбара 244px, сверху и справа 8px, снизу 8px + высота нижней панели агента 28px).
   - Тёмная: фон `#09090a`, панель `#121213`, рамка `#212224`. Светлая: фон `lch(94.44% 0.5 282)`, панель `lch(97.94% 0.5 282)`, рамка `lch(88.49% 0 282)`.
   - Белой вспышки в тёмной теме нет: тема и цвета ставятся inline-скриптом до первой отрисовки.
2. **Если загрузка длится больше 1 с** — по центру панели проявляется логотип Linear 32px (`fadeIn .4s ease-out` с задержкой 1s), цвет `#6b6f76` в тёмной и `#b0b5c0` в светлой. Через 1.2 с после `DOMContentLoaded` вокруг него пульсирует кольцо 64px: `logoBackgroundPulse 3.2s ease-out infinite` — scale .8→1, opacity 0→1 (70%)→0, обводка тем же цветом с прозрачностью .4.
3. **Через 8 с** под логотипом появляется «Loading…» (13px, `opacity` за .8s с задержкой .8s). При ошибке сети заставка превращается в «Network error while loading» с кнопками.
4. **Готово** — приложение отрисовывается под заставкой, `body.loaded` убирает её за 100 мс (`opacity`), кольцо ставится на паузу. Рамка не двигается: настоящая панель стоит ровно на её месте, поэтому глаз видит только появление содержимого.

На тёплой перезагрузке шаги 2–3 не наступают: FCP ≈ 1.04 с, LCP ≈ 1.08 с, и человек видит только пустую рамку → приложение.

### Где это живёт

Всё — в первом HTML-документе, до любых скриптов приложения:

- inline `<script>` в `<head>` читает `localStorage.splashScreenConfig` (`darkMode`, `bgSidebarColor`, `bgBaseColor`, `bgBorderColor`, `sidebarWidth`, `agentToolbarHeight`) — приложение само записывает туда свои текущие цвета и размеры, поэтому заставка совпадает даже с пользовательской темой и ширинами. Тот же скрипт ставит `html.dark`, `<meta name="theme-color">` и `color-scheme`.
- inline `<style>` (~6 КБ): переменные двух тем, `#loading`, `#appBorders`, `#loading-content`, ключевые кадры `logoBackgroundPulse` и `fadeIn`, медиазапросы ≤1023px и ≤880px (рамка во всё окно).
- inline `<script>` в `<body>`: класс `logged-out`, если в `localStorage` нет `ApplicationStore` или открыт адрес входа — тогда рамки нет, только фон; класс `electron` для десктопа.
- разметка `#loading > #appBorders > #loading-content > svg.bkg + svg#logo + #loadingText` стоит после `#root`.

## Как устроен Linear

| | Linear |
|---|---|
| Первый HTML | 32 КБ, `cache-control: private, max-age=0, stale-while-revalidate=1800`; inline-заставка и критический CSS, `preconnect` к `static.linear.app`, `preload` шрифта Inter Variable, основной CSS грузится с `media=print` и переключается после загрузки (не блокирует отрисовку) |
| Фронтенд | React + MobX (чанки `mobx`, `SyncedStore`, `ApplicationStore`), сборка Rolldown/Vite (`rolldown-runtime`), ES-модули: 1 входной скрипт + 124 `modulepreload` в HTML, всего ≈250 JS-чанков с хэшами в именах на `static.linear.app` |
| Данные | Собственный sync engine: модели в IndexedDB (`ClientStorage`, `SyncedStore`), изменения как транзакции (`CreateTransaction`), дельты по WebSocket, GraphQL для запросов. Интерфейс рисуется из локальной базы до ответа сети, поэтому повторная загрузка не ждёт API |
| Кэш и офлайн | Service worker (`/client/sw.js`) отдаёт чанки из кэша: на перезагрузке у JS `transferSize = 0` |
| Инфраструктура | Cloudflare (CDN, HTTP/3 `alt-svc: h3`), статика на отдельном домене, `nonce`-CSP для inline-скриптов |
| Тайминги, тёплая перезагрузка | TTFB ≈ 125 мс, DCL ≈ 300 мс, first paint ≈ 350 мс (рамка), FCP ≈ 1.04 с, LCP ≈ 1.08 с |

## Что стоит позаимствовать дальше

Каждый пункт — отдельная задача, если владелец решит её брать:

1. **Последовательная цепочка запросов при старте.** `accounts → me → accounts` идут друг за другом (≈ 470 мс до первого запроса данных). Один стартовый эндпоинт (`/api/bootstrap`: аккаунты, профиль, настройки вида) или параллельный запуск сократит время до содержимого примерно вдвое.
2. **Локальный кэш для мгновенной первой отрисовки.** Как у Linear: сохранять последние ответы Inbox/списков в IndexedDB и рисовать их сразу, обновляя по ответу сети.
3. **Разделение бандла.** Один чанк ≈ 1 МБ: Settings, Ads Manager, графики и редактор правил можно грузить лениво (`React.lazy`), а входной чанк — подгружать `modulepreload`.
4. **Service worker для статики.** Чанки с хэшами можно отдавать из кэша, как у Linear, — перезагрузка перестанет зависеть от сети для JS/CSS.
5. **Неблокирующий CSS.** Основной CSS у Linear не блокирует первый кадр (заставка обходится inline-стилями); у Buyerly то же можно сделать после пункта 3.
